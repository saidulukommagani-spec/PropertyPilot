# PropertyPilot Architecture Inventory

Repository inspection snapshot. Main runtime is `propertypilot-backend` (Spring Boot 3.5 / Java 21 / PostgreSQL / Flyway). `backend/`, `database/`, `admin-portal/`, and `infrastructure/` contain only placeholder files; `propertypilot-frontend` is a React/TypeScript client; `mobile_app` is a sparse Flutter shell. The independent `my-database-migration-project` is not wired into the runtime backend.

## Modules and dependencies

- **Web:** `web/controller` -> application service interfaces -> `application/service/impl` -> repositories -> JPA entities.
- **Domain:** enums and workflow/business status values consumed by services/entities.
- **Persistence:** `infrastructure/persistence/entity` maps core and extended models; `repository` is Spring Data JPA.
- **Security/config:** JWT filter/service, user details, `SecurityConfig`, password and OpenAPI configuration.
- **Operations:** subscription reminder, expiry and auto-renew schedulers; actuator health/info; Docker image and Compose.
- **Frontend clients:** `propertypilot-frontend/src` and `mobile_app/lib`; no `admin-portal` implementation found.

## Cross-module dependency notes

- Authentication maps user records and roles into JWT-derived Spring authorities; controllers rely on URL matchers and optional method annotations.
- Service requests depend on customer, property, service catalog, eligibility, assignment, status history, billing, and completion validation.
- Completion validation depends on service configuration, visits, evidence types/evidence, and GPS verification.
- Pricing reads pricing profile parameters; current calculator response is not visibly persisted to estimate/quote line-item entities.
- Subscription schedulers depend on subscription, plan-version, renewal, and notification stores; auto-renew currently has no payment-provider dependency.
- Visits depend on accepted agent assignments. Agent assignment lifecycle has a second interface/implementation whose operations are deferred to service-request/visit workflows.
- Legacy schema includes Marketplace/Vendor/Partner/Complaint/Monitoring/NRI/OfflineSync/Refund types alongside the PropertyPilot-managed service model.
